0本讲导读Read Me First

讲法。这一讲不教任何课程内容，只回答一个问题：你写的那份 Python 数据，是怎么变成一本能打印的 PDF 的。

这一节能解决什么。让你在十分钟内看懂仓库里每个目录在流水线的哪一段，并且能自己改一个字、再生成一份。

这一节不能解决什么。不解释三道门的判据为什么这样定（那是 `docs\使用\03-三道门.md` 的事），也不讲怎么写出好例题。

整条线一份数据（D01.py）→ 讲义源（source html） HTML → 过内容门（content gate） → 无头浏览器（headless browser）打 PDF → 过版式门（layout gate） → 成品。

引用写法：真实课程会标成「课件 p.N」，指向源 PDF 的页序；示例课程没有源课件，N 仅作格式演示（如课件 p.1）。

1一份讲义由什么组成Anatomy of a Handout

讲法。先看目录与文件名，再看那张表：仓库里每一样东西，只负责流水线的一段（依据：仓根目录树，§1）。

目录它是什么谁改它
engine\生成器：数据 → HTML → PDF → 两道门开发者
<课程>\_lessons\讲义数据（lesson data）（每讲一个 .py，变量名 LESSON）写内容的人
<课程>\01_讲义\成品 PDF（生成物，不进 Git）没人手改
tools\print\打印与检查：audit_lesson、pdf.js、KaTeX开发者
ui\本地界面：看成品、生成、阅读、记笔记（note）开发者
一条命令走完四步，中间不手动开浏览器engine\_make.py 做四件事：
1 读 <课程>\_lessons\D01.py 的 LESSON
2 渲染成 HTML（含目录、公式、结构图）
3 调本机 Edge/Chrome 无头打 PDF
4 过内容门与版式门，红项不出货
一份讲义要求「每节至少有一段代码或一道例题」，这条是由谁保证的？
  1. 由内容门（audit_lesson.py --content）保证，不是靠自觉
  2. 它逐节扫 
     与 
    ，缺一即红
  3. 所以写数据的时候，每节都要带上其中一样
答案：内容门。人只负责写对，机器负责不漏。

2三道门各查什么What the Three Gates Check

讲法。三道门是三种不同性质的检查：内容有没有、版式对不对、图有没有破（判据实现见 `tools\print\audit_lesson.py`，§2）。任何一门红，都不许出货。

门查什么红了怎么办
内容门（content gate）每节是否有代码/例题；术语首次出现是否附英文补内容，不改判据
版式门（layout gate）每页首行是否是标题/表格/图（不能是正文半行）调分页（pagination）：补小标题或删表
破图门（broken image）图片宽高是否小于 32px（Chrome 缺图图标）把素材放回对应目录
版式门报「第 7 页首行是正文」，你有哪两种改法？
  1. 在该页之前补一个真实的小标题（h3），让新页从标题起
  2. 或者把跨页的那段拆开/删掉一小段，让正文不落在页首
  3. 两种都不许改版式门的白名单（whitelist）——判据不是用来迁就排版的
答案：补标题或调内容；改判据等于把门拆了。
红项不会自动变绿，必须人改内容python engine\_make.py D01
# 输出会逐项打印 OK / WARN / FAIL；有三行 OK 才算过完三道门

3自己跑一遍Run It Yourself

讲法。这一节只有一件事：动手。改一个字，重新生成，看着它变。

第一次跑会给 10–20 秒；之后同一份数据再跑仍然要全量重建$env:PLUMA_COURSE='DEMO'
python engine\_make.py D01
# 然后打开 DEMO\01_讲义\D01_一份讲义是怎么出来的_讲义.pdf

改这一讲最省事的入口：把上面 §1 那张表的「谁改它」一列随便改两个字，重新跑一遍，看 PDF 里是不是真的变了。改完记得改回来。

如果生成后 PDF 没变化，最可能的原因是什么？
  1. 命令跑的是另一门课（没设 PLUMA_COURSE，用的是默认课程（default course））
  2. 或者改的不是 LESSON 里的数据，而是注释/文档
  3. 第三可能：PDF 被别的程序占用，写入失败——输出里会有 FAIL
答案：先看输出里读的是哪个目录、哪一讲，再怀疑缓存。

4本讲小结Takeaways

讲法。收口用一张表：每条都配一个能自己验的动作，不写虚无的话。

记住什么一句话怎么自查
流水线数据 → HTML → PDF → 三道门改一个字再跑 `_make.py`
数据在哪`<课程>\_lessons\<讲号>.py` 的 `LESSON`打开文件看 sections
谁不让出货内容门 / 版式门 / 破图门看生成输出的 OK / FAIL 行
课程怎么切`PLUMA_COURSE` 环境变量（默认取 courses.json 第一门）`$env:PLUMA_COURSE='DEMO'`

如果只带走一句：讲义是「数据 + 三道门」的产物，不是手写出来的；改数据、重跑、看门报告，这条线在任何一个课程里都一样。

5自测Self-check

讲法。四题都是「你要去哪儿改、改完看哪个输出」，不考背诵。

Q1. 想让某一节多一段代码，改哪个文件？
答：`<课程>\_lessons\<讲号>.py` 里那个节的 `body`，加一条 `("code", 语言, 代码, 说明)`；不是改 HTML。回看 §1。
Q2. 生成后 PDF 里没有你刚加的那段，先查什么？
答：看命令输出里读的是哪门课、哪一讲——没设 `PLUMA_COURSE` 时会跑默认课程。回看 §3。
Q3. 内容门报「第 2 节没有代码或例题」，两种改法？
答：给该节加 `code` 或 `eg` 块；或者该节本来就只是过渡，把它并到相邻节。**不许改门**。回看 §2。
Q4. 为什么成品 PDF 不进 Git？
答：它是生成物，重跑即可再生；而且体积大、每次生成字节都不同，入库只会把仓撑胖。回看 §1。

7附录Appendix

讲法。一张命令速查 + 一组新手常见误解。

符号 / 缩写读法·含义出处
`PLUMA_COURSE`指定默认课程（不设则取 courses.json 第一门）本讲 §3

常见误解

  1. 把讲义当成手写的：它是数据渲染出来的，改 HTML 下次重跑就没了。
  2. 以为门红了可以改判据：门是用来拦内容的，改门等于拆门。
  3. 以为 PDF 该进 Git：它是生成物，重跑即可再生。
  4. 忘了设 `PLUMA_COURSE` 就以为代码没生效：先看输出里读的是哪门课。
