## 3. token

- 问课件的提问包实测 **1,280 字符**（TOP_K=5 × 420 字符 + 节号页码），检索耗时 **< 1 s**，不花钱模式可用。
- 结论：**没有可压的空间而不改回答质量**。压 TOP_K 或段长会改变给模型的证据集 → 属于改行为，不算零变更。
- 可做的只有「重复问题响应缓存」（顾问建议 ②-2），但会返回旧回答作为新回答，风险高于收益，本轮不做。

- 增量构建（顾问建议 ④-1）：单讲 7 s，收益也就是 7 s → 4 s，且引入「指纹漏项复用旧产物」风险。**不建议**。

## 6. 架构

**已做：静态资源加 ETag + 304**（2026-11-17）

- 改法：`ui\server.py` 新增 `_static()`，`/pdfjs/` 路由改用它；`index.html`、PDF 下载、JSON 仍走 `_file()` 的 `no-store`。
- 实测（`--port 8799` 临时实例，跑完即关）：
  - 首次 `GET /pdfjs/pdf.min.mjs` → **200**，`ETag: "49e26487d87a86cb96f6a21740cf7e67"`，`Cache-Control: no-cache`，`Content-Type: text/javascript`，**336,222 字节，与磁盘完全一致**；
  - 带 `If-None-Match` 再取 → **304**（无 body）；
  - `GET /` → `Cache-Control: no-store`、无 ETag（未被污染）；
  - `GET /pdfjs/nope.mjs` → **404**（原 404 行为保留）。
- 收益：1.66 MB（worker 1.33 + 主包 0.33）从「每次全量传」变为「首次一次、之后 0 字节」。
- 回滚：删 `_static()` 并把路由改回 `self._file`。
