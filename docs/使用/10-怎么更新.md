# 怎么更新

最后核对：2026-11-21 · 适用 v1.9.15

一句话：**文件夹版的更新就是「换文件」——`git pull` 或重新下载压缩包覆盖，再双击 `启动羽毛笔.cmd`。**

## 文件夹版（v1.9.15 起）

1. 有 Git：在仓库目录跑 `git pull`。
2. 没 Git：重新下载仓库压缩包，解压后覆盖到同一目录（先备份 `courses.json` 与自己的课程目录）。
3. 重新双击 `启动羽毛笔.cmd`；设置页的版本号变了就是更新成功。

> 下面讲的「立即更新」是旧的单文件 exe 方案（下载 114 MB、替换 `LaPluma.exe`）。v1.9.15 起不再提供单文件包，这条路径只在旧版本里有效，留作历史说明。

## 旧：应用内更新（单文件版，已退役）

以下内容只对 v1.9.14 及更早的单文件 exe 有效，留作历史说明。

## 两种方式，什么时候用哪个

| | 在线更新（推荐） | GitHub |
|:--|:--|:--|
| 怎么触发 | 右下角卡片点「立即更新（114 MB）」 | 卡片点「去看看」，或自己开仓库 Releases |
| 需要浏览器吗 | 不需要，全程在应用里 | 需要 |
| 包从哪来 | 项目自建的更新清单（`feed/latest.json`） | GitHub Releases 页面 |
| 校验 | 下完自动核对大小与 SHA-256，不对就不装 | 无（靠浏览器下载完整性） |
| 装完 | 自动备份旧文件为 `.bak`，替换后重启 | 手动解压 / 替换 |
| 适合 | 日常升级 | 想看每一版改了什么、或网络连不上清单时 |

两条渠道读的是同一份版本号：清单连不上会自动退回 GitHub 渠道，界面上的卡片照常出现，只是按钮从「立即更新」变成「去看看」。

## 在线更新会做什么

1. 打开界面时问一次更新源（6 小时内不重复问），有新版本才弹卡。
2. 点「立即更新」→ 进度条走起来，状态行写「正在下载 42%（48 MB / 114 MB）」。
3. 下完先核对：字节数要对，清单给了 SHA-256 就必须一致；不对立即报错，旧版本不受影响。
4. 核对通过后生成本机的 `apply.bat`：等程序自己退出 → 把旧 exe 备份成 `LaPluma.exe.bak` → 把新文件换上去 → 重新启动 → 删掉自己。
5. 窗口会自动关掉再开，标题栏的版本号就是新的。

想确认更新真的发生了，看两处：

- 标题栏 / 设置页的版本号；
- `%USERPROFILE%\.pluma\update\update.log`（每次替换都会写一行 `replaced ok`）。

## 出问题怎么办

| 现象 | 怎么查 | 怎么改 |
|:--|:--|:--|
| 点了「立即更新」没反应 | 状态行写什么？「没能开始下载」说明清单取不到 | 换网络或稍后重试；也可以走 GitHub |
| 下载到一半失败 | 状态行会写原因（超时、校验值不对…） | 再点一次；重下会覆盖半截文件 |
| 重启后版本号没变 | 看 `update.log` 最后一行 | 若是 `replace failed`，说明目标文件被占用：关掉程序再手动替换 |
| 新版本打不开 | 同目录有 `LaPluma.exe.bak` | 把 `.bak` 改名回 `LaPluma.exe` 即可退回上一版 |

## 为什么以后要分「资源包」和「exe 本体」

exe 一百多 MB，大部分是界面、脚本、示例课程、文档这些**不常变**的东西；
只改了文档或示例时，让用户重下 114 MB 是浪费。所以清单里留了两个位置：

- `assets.exe`：程序本体（`LaPluma.exe`），改了代码才需要换；
- `assets.res`：资源包（`LaPluma-res.zip`），改了文档 / 示例 / 字体时才需要换。

现在两个都支持下载与校验；资源包的解压替换已写进同一个 `apply.bat`（解到程序所在目录），
目前发布流程只发 exe，等资源包第一次真正拆分时才启用 `res`。

## 发布侧（维护者看）

```powershell
# 打完包之后生成清单：大小与 SHA-256 由脚本现算，摘要与条目从 CHANGELOG 抽
python tools\build\make-feed.py --version 1.9.5 --exe dist\LaPluma.exe
# 有资源包时再加 --res dist\LaPluma-res.zip
```

清单写到 `feed\latest.json`，随仓库发布；应用按 raw → jsDelivr 两个源依次读，
一个不通就用下一个。清单格式变了要同步改 `ui\server.py` 里的 `FEED_SCHEMA`，
判据 `python tools\check\check-update.py` 会红着提醒。
