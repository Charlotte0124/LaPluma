# 怎么更新

最后核对：2026-11-24 · 适用 v1.9.18

一句话：**文件夹版的更新就是「换程序文件」——应用内点「立即更新」，或下载压缩包解到新目录再启动；两条路都保留课程与笔记。**

## 一、应用内更新（v1.9.18 起）

1. 打开软件，右下角会出现「有新版本」卡片；设置页「版本」那一行也会写「仓库 vX · 有新版本」。
2. 点「立即更新（约 13 MB）」：下载 → 校验字节数 / SHA-256 → 窗口自动关掉再开。
3. 新版**只覆盖程序文件**（`ui` / `engine` / `tools` / `docs` 等）；`courses.local.json`、你的课程目录、`out`、`_logs`、`_trash` 一个都不动，`courses.json` 也不会被覆盖。
4. 日志在 `%USERPROFILE%\.pluma\update\apply.log`；被覆盖的旧文件备份在 `%USERPROFILE%\.pluma\update\backup-<版本>-<时间>\`。
5. 新版本打不开：把备份目录里的文件拷回程序目录，或直接重新解压上一版压缩包。

> 卡片 24 小时内只弹一次；想手动再查，打开「设置」看「版本」那行，它每次都现查。
> 更新源：`feed/latest.json`（随仓库发布）优先，GitHub Releases 兜底；两边都连不上时只提示「读不到仓库版本」，不影响使用。

## 二、手动更新（下载压缩包）

1. 下载 `LaPluma-<版本>.zip`，解压到**任意新目录**（不必覆盖旧目录）。
2. 双击新目录里的 `启动羽毛笔.cmd`。首次启动会自动找旧版本目录，把课程导进来，并用一个系统弹窗列出导入了什么。
3. 没自动找到旧目录时，手动导入：

```powershell
cd <新目录>
python upgrade.py --list
python upgrade.py --from "D:\旧版\LaPluma" --dry-run   # 先看会复制什么
python upgrade.py --from "D:\旧版\LaPluma"             # 真复制
```

4. 旧目录保持原样；确认新版能打开、课程都在，再删旧目录。

## 三、为什么以前升级会「课程不见」

文件夹版的数据根就是**程序目录本身**（`paths.py`）：`courses.local.json`、`<课程>\`、`out`、`_logs`、`_trash` 都在程序目录里。
把新压缩包解到一个新文件夹，新文件夹当然没有旧课程——不是升级删了它们，是两份目录各存各的。

发布包只含 Git 里的示例课程 `DEMO`；真实课程名与课件不进公开仓（见 AGENTS 十四），所以也不能靠压缩包带过来。
v1.9.18 起由 `upgrade.py` 负责导入：

- 自动：新目录首次启动、且当前还没有用户数据时，按 `%USERPROFILE%\.pluma\install.json` 记的上一次数据根 → 同级目录 → `Downloads` / `Desktop` 里名字像 LaPluma 的目录去找，找到就补进来；旧目录不动。
- 手动：`python upgrade.py --from <旧目录>`；加 `--dry-run` 只看计划。
- 目标已有的同名文件不覆盖；导入完写 `_logs\upgrade-import-<时间>.json`（逐项文件数、字节数、校验结果）。

## 四、卸载旧版显示「正在占用」

旧版窗口关了不等于进程一定退出；卸载器要删 `ui\server.py` 之类正在被 `pythonw.exe` 打开的文件，于是报「正在占用」。

1. 先关旧版窗口；
2. 还不行就结束旧实例：

```powershell
cd <旧版或新版目录>
python upgrade.py --stop-old            # 只列出占用 8765-8775 的 Python 进程（含命令行）
python upgrade.py --stop-old --kill     # 确认是羽毛笔后再结束
```

3. 或在任务管理器里结束 `pythonw.exe` / `python.exe`（命令行里带 `ui\server.py` 的那个），再卸载。

## 五、出问题怎么办

| 现象 | 怎么查 | 怎么改 |
|:--|:--|:--|
| 打开是浏览器页，不是软件窗口 | 启动器日志 `%USERPROFILE%\.pluma\logs\launcher.log` 里 `pywebview=` 是不是 False | 双击 `启动羽毛笔.cmd` 让它自动装 pywebview；或 `python -m pip install pywebview` |
| 弹窗说窗口打不开 | 弹窗里的记录路径（`_logs\startup.log`） | 多数是缺 WebView2 运行时：装 [Microsoft Edge WebView2](https://developer.microsoft.com/microsoft-edge/webview2/) 后重开 |
| 卡片没出现 | 设置页「版本」那行写什么 | 写「仓库 vX · 已是最新」就是真没有新版；写「读不到」是网络；也可看 `feed/latest.json` 的 `latest` |
| 点「立即更新」没反应 | `%USERPROFILE%\.pluma\update\apply.log` | 下载失败会写原因；重试或走手动更新 |
| 更新后课程没了 | `courses.local.json` 和课程目录还在不在 | 还在：用 `python upgrade.py --from <旧目录>` 导入；不在：从备份恢复 |
| 更新后版本号没变 | `apply.log` 最后一行 | 出现 `folder apply FAILED` 会回滚并重启旧版；按日志里的原因处理 |

## 六、发布侧（维护者看）

```powershell
cd F:\DSH\apps\LaPluma
python tools\build\make-zip.py --version 1.9.18
python tools\build\make-feed.py --version 1.9.18 --app dist\LaPluma-1.9.18.zip
```

顺序不能反：清单里的 `sha256` 必须就是上传到 Release 的那个 zip。
`make-zip.py` 只打包 Git 里的文件，并剔除 `feed/latest.json`——所以改清单不会改变发布包的 sha256。
清单格式变了要同步改 `ui\server.py` 的 `FEED_SCHEMA`；判据 `python tools\check\check-update.py` 会红着提醒。
