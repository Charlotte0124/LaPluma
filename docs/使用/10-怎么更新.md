# 怎么更新

最后核对：2026-11-25 · 适用 v1.9.19

一句话：**从 v1.9.19 起，课程放在「课程库」里，更新只换程序文件；第一次在新文件夹启动时，若检测到旧版本，会先问你要「直接改用 / 复制过来 / 不用」，不再偷偷导入。**

## 一、先弄清「课程库」在哪

课程库 = 存 `courses.local.json`、各课程目录、`out`、`_logs`、`_trash` 的那个文件夹。

- **默认**：程序目录本身（与以前一样，老用户不受影响）。
- **建议改成独立文件夹**：打开「设置 → 课程库位置 → 换一个文件夹…」，选一个空目录（例如 `D:\羽毛笔库`）。以后换任何版本的羽毛笔，课程都在那里，不随程序目录走。
  - 「直接改用」：不复制，重启后课程就在那个文件夹里。
  - 「复制过去再改」：把当前库里的课程复制进新文件夹，再切过去；旧位置保持原样。
  - 改库位置要**关闭软件重新打开**才生效。
- 命令行等价操作（在程序目录里）：

```powershell
python upgrade.py --where                       # 当前库在哪
python upgrade.py --set-library "D:\羽毛笔库"    # 换库（重启生效）
python upgrade.py --clear-library               # 恢复默认：库 = 程序目录
```

> 库指定为别的文件夹后，不要拿它当程序目录用；它是纯数据目录。
> 把库放在移动硬盘 / 网络盘上也可以，但盘没接上时软件会退回程序目录并弹窗提示。

## 二、应用内更新（v1.9.18 起）

1. 打开软件，右下角会出现「有新版本」卡片；设置页「版本」那一行也会写「仓库 vX · 有新版本」。
2. 点「立即更新（约 13 MB）」：下载 → 校验字节数 / SHA-256 → 窗口自动关掉再开。
3. 新版**只覆盖程序文件**（`ui` / `engine` / `tools` / `docs` 等）；`courses.local.json`、你的课程目录、`out`、`_logs`、`_trash` 一个都不动，`courses.json` 也不会被覆盖。
4. 日志在 `%USERPROFILE%\.pluma\update\apply.log`；被覆盖的旧文件备份在 `%USERPROFILE%\.pluma\update\backup-<版本>-<时间>\`。
5. 新版本打不开：把备份目录里的文件拷回程序目录，或直接重新解压上一版压缩包。

> 卡片 24 小时内只弹一次；想手动再查，打开「设置」看「版本」那行，它每次都现查。
> 更新源：`feed/latest.json`（随仓库发布）优先，GitHub Releases 兜底；两边都连不上时只提示「读不到仓库版本」，不影响使用。
> **v1.9.17 及更早不能一键升到 v1.9.19**：那些版本的更新代码只认 `.exe`。先手动下载一次 v1.9.19，之后就能在软件内更新。

## 三、手动更新（下载压缩包）

1. 下载 `LaPluma-<版本>.zip`，解压到**任意新目录**（不必覆盖旧目录）。
2. 双击新目录里的 `启动羽毛笔.cmd`。如果检测到以前的课程库，会弹「检测到以前的课程库」：
   - **直接改用这个库**：软件以后就读那个文件夹，不复制，重启一次课程就都在（推荐）。
   - **复制到当前目录**：把旧课程复制进当前目录，旧文件夹保持原样。
   - **不用**：记下来，下次不再问；以后可在「设置 → 课程库位置」里改。
3. 没检测到旧目录时，手动指定：

```powershell
cd <新目录>
python upgrade.py --list                                # 找可能的旧目录
python upgrade.py --set-library "D:\旧版\LaPluma"      # 直接把库定到旧目录（不复制）
python upgrade.py --from "D:\旧版\LaPluma" --dry-run   # 或先看会复制什么
python upgrade.py --from "D:\旧版\LaPluma"             # 真复制到当前库
```

4. 旧目录保持原样；确认新版能打开、课程都在，再决定删不删旧目录（库若指向旧目录，**不要删**）。

## 四、为什么以前升级会「课程不见」

文件夹版的数据根就是**程序目录本身**（`paths.py`）：`courses.local.json`、`<课程>\`、`out`、`_logs`、`_trash` 都在程序目录里。
把新压缩包解到一个新文件夹，新文件夹当然没有旧课程——不是升级删了它们，是两份目录各存各的。

发布包只含 Git 里的示例课程 `DEMO`；真实课程名与课件不进公开仓（见 AGENTS 十四），所以也不能靠压缩包带过来。
v1.9.19 起有两条路：

- **库位置**：「设置 → 课程库位置」把库定在旧目录或任意独立文件夹，新版直接读它，不复制。
- **导入**：检测到旧版本时由你选「直接改用 / 复制过来 / 不用」；也可 `python upgrade.py --from <旧目录>`。
  导入只补目标没有的文件（同名不覆盖），旧目录不动，结果写 `_logs\upgrade-import-<时间>.json`。

## 五、卸载旧版显示「正在占用」

旧版窗口关了不等于进程一定退出；卸载器要删 `ui\server.py` 之类正在被 `pythonw.exe` 打开的文件，于是报「正在占用」。

1. 先关旧版窗口；
2. 还不行就结束旧实例：

```powershell
cd <旧版或新版目录>
python upgrade.py --stop-old            # 只列出占用 8765-8775 的 Python 进程（含命令行）
python upgrade.py --stop-old --kill     # 确认是羽毛笔后再结束
```

3. 或在任务管理器里结束 `pythonw.exe` / `python.exe`（命令行里带 `ui\server.py` 的那个），再卸载。
4. **卸载前先看库在哪**：`python upgrade.py --where`。库若就在旧程序目录里，删目录会连课程一起删——先把库改到别处或复制出来。

## 六、出问题怎么办

| 现象 | 怎么查 | 怎么改 |
|:--|:--|:--|
| 打开是浏览器页，不是软件窗口 | 启动器日志 `%USERPROFILE%\.pluma\logs\launcher.log` 里 `pywebview=` 是不是 False | 双击 `启动羽毛笔.cmd` 让它自动装 pywebview；或 `python -m pip install pywebview` |
| 弹窗说窗口打不开 | 弹窗里的记录路径（`_logs\startup.log`） | 多数是缺 WebView2 运行时：装 [Microsoft Edge WebView2](https://developer.microsoft.com/microsoft-edge/webview2/) 后重开 |
| 课程列表空了 | 设置页「课程库位置」写的是哪；有没有红字「上次设的库找不到」 | 库在移动硬盘 / 网络盘上：接上再开；库被删：重新选库，或 `--from` 从旧目录导 |
| 换了库位置没变化 | 是否关了软件重新打开 | 改库位置要重启才生效；没重启时读的还是旧库 |
| 卡片没出现 | 设置页「版本」那行写什么 | 写「仓库 vX · 已是最新」就是真没有新版；写「读不到」是网络；也可看 `feed/latest.json` 的 `latest` |
| 点「立即更新」没反应 | `%USERPROFILE%\.pluma\update\apply.log` | 下载失败会写原因；重试或走手动更新 |
| 更新后课程没了 | `courses.local.json` 和课程目录还在不在 | 还在：用 `python upgrade.py --from <旧目录>` 导入；或把库位置指过去；不在：从备份恢复 |
| 更新后版本号没变 | `apply.log` 最后一行 | 出现 `folder apply FAILED` 会回滚并重启旧版；按日志里的原因处理 |

## 七、发布侧（维护者看）

```powershell
cd F:\DSH\apps\LaPluma
python tools\build\make-zip.py --version 1.9.19
python tools\build\make-feed.py --version 1.9.19 --app dist\LaPluma-1.9.19.zip
```

顺序不能反：清单里的 `sha256` 必须就是上传到 Release 的那个 zip。
`make-zip.py` 只打包 Git 里的文件，并剔除 `feed/latest.json`——所以改清单不会改变发布包的 sha256。
清单格式变了要同步改 `ui\server.py` 的 `FEED_SCHEMA`；判据 `python tools\check\check-update.py` 会红着提醒。
