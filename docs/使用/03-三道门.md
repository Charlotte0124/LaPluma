# 三道门

一句话：**门红了不出货，这是 `return 1`，不是建议。**

## 三门分别判什么

| 门 | 命令 | 判据（红了就是不合格） |
|:--|:--|:--|
| 源门 | `python tools\src\source_audit.py` | 课件引用对不上、图注为空 |
| 内容门 | `python tools\print\audit_lesson.py --content --file <源.html>` | 缺 `data-reader`；有公式但无符号表；某节缺讲法；术语未在节内首次附英；单段 >210 字 |
| 版式门 | `python tools\print\audit_lesson.py CS340` | 页首是正文（应为标题/表格/图注）；出现空白残页 |

> **出处核验（2026-11-23 加，只报告不拦）**：内容门跑的时候会顺带做 `--cite-verify`——把每一处「课件 p.N」按句与原件第 N 页的文字比重合，重合低于阈值、而另一页明显更高时，打印「疑似标错 · 标了 p.N · 重合 X% · 建议核对 p.M」。它**不进 FAIL、不改退出码**，因为阈值只在本机 3 份课件上校准过（覆盖不了跨语言引文：中文讲义引英文课件时只有引文里保留的英文术语可比）。当「待人工核对」用，别当判决。
>
> 单独跑：`python tools\print\audit_lesson.py --cite-verify`。

> **源门要一份来源清单**（`*_sources.md`，逐条列 S1/S2/S3 与核验状态）。仓库不带你的清单，所以刚 clone 下来跑它会说找不到清单——**那叫「没查」，不算「通过」**。想让源门真跑，先放清单再跑。

## 怎么看结果

`OK n · WARN m · FAIL k`：

- `FAIL 0` 才算过；
- `WARN` 是提醒，不拦，但要有人看过并说一句「为什么不改」；
- 最后那行「人工仍需抽查」不是客套：**脚本判不了类比是否误导、例题数字是否算对**。跳过不等于通过。

## 版式门红了怎么改

```powershell
python engine\_pagediag.py L02
```

它逐页打出「填充高度 + 首行字体字号 + 首行文字」，标出「页首是正文」的页。

| 现象 | 改法 |
|:--|:--|
| 整节能搬走就搬走 | 让这节整体挪到下一页 |
| 节内确实超一页 | 在块边界插 `<div class="pb"></div>` |
| 段落跨页只剩两行 | 补一个真实的小标题，或删掉最长的表 |

不要用「每节起新页」的粗暴办法——会造出一堆只占四分之一页的空页。

## 一条不可违反的规矩

**不许为了变绿改检查器。** 阈值调低、判据放宽、把红项加进白名单，这些都不是修，是掩盖。要改判据，先改规矩本身并留痕。
