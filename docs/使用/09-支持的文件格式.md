# 支持的文件格式

> 一句话：**PDF 与图片是原生支持；Word、PowerPoint、纯文本、Markdown 导入时自动排成分页 PDF**，之后所有环节（阅读、页码定位、三道门、导出）走的是同一条路。

## 一、能导进来什么

| 格式 | 后缀 | 怎么处理 | 页数怎么算 | 局限 |
|:--|:--|:--|:--|:--|
| **PDF** | `.pdf` | 原生：直接用 | 文件自己的页 | 扫描件没有文字层，只能看图读（软件会把页面渲染成图给模型看） |
| **图片** | `.png` `.jpg` `.jpeg` | 原生：一张图一页 | 一个文件一页 | 手写字、糊图、长截图都会掉精度 |
| **Word** | `.docx` | 导入时抽文字，排成 A4 分页 PDF，旁边生成「`<原名>（转换）.pdf`」 | 每页约 34 行 | 只抽文字：公式、图表、图片、批注、页眉页脚会丢；老格式 `.doc` 不支持（用 Word 另存为 `.docx`） |
| **PowerPoint** | `.pptx` | 导入时抽文字，**一张幻灯片一页** | 幻灯片张数 | 只抽文字：图片、图表、动画、备注页会丢；老格式 `.ppt` 不支持（另存为 `.pptx`） |
| **纯文本** | `.txt` | 按行排，每页约 40 行 | 行数 / 40 | 不做任何排版还原 |
| **Markdown** | `.md` | 去掉 `#`、反引号、列表符号后按行排 | 行数 / 40 | 表格会变成一行行文字 |

> 转换件命名规则：原件 `第9讲 虚拟内存.docx` → 转换件 `第9讲 虚拟内存（转换）.pdf`，就在同一目录（`<课程>\00_原件\`）。
> 原件不会被动；想重新转换，把「（转换）」那一份删掉再导入一次即可。

## 二、怎么导进来（三个入口）

| 入口 | 操作 |
|:--|:--|
| 课程抽屉 | 点课程卡 → 抽屉顶部「＋ 导入课件」→ 系统文件对话框（可多选） |
| 拖拽 | 把文件直接从资源管理器拖进窗口 |
| 生成页 | 「原件 → 讲义」区也能添加原件 |

导入后会自动建一讲骨架（讲号从文件名里的数字推出来，例如 `Tutorial 02.pdf` → `T02`），这样「要生成的批次」里立刻能看到它。

## 三、文件与体积

- **单个文件上限 50 MB**（走网页上传时）。超过就用「选择文件」那个入口——它在本机直接复制，不过网络。
- 转换件通常比原件小得多（实测：一份 3 页 Word 讲义 → 88 KB 的 PDF）。
- 转换在本机做，不上传、不联网。

## 四、为什么 Word / PPT 要先转成 PDF

讲义流水线的定位全靠**页**：每条引文都要标「课件 p.N」，版式门会检查这个标注能不能对回原件。Word 与 PowerPoint 本身没有稳定的页概念（换台电脑、换个字体，页就变了），所以：

1. 导入时立刻排成分页 PDF，页数固定、可回查；
2. 之后阅读、提问、三道门、导出全都不用改；
3. 你随时可以打开那份「（转换）.pdf」核对模型引用的到底是哪一页。

代价是：**只抽文字**。如果课件的关键信息在图上、公式里、或者是一份扫描件，Word/PPT 这条路会丢东西——那就把原件导出成 PDF（图片型）再导入，软件会按图读。

## 五、格式选哪个更稳

| 你的课件是 | 建议 |
|:--|:--|
| 学校发的 PDF 讲义 | 直接导入 PDF（最好是文字版，不是扫描） |
| 老师发的 PPT | 导入 `.pptx`；如果有大量公式/示意图，先在 PowerPoint 里「另存为 PDF」再导入 |
| 自己写的 Word 讲义 | 导入 `.docx`；排版复杂就另存为 PDF 再导入 |
| 手写笔记 / 拍照板书 | 图片导入，一张一页 |
| 代码或纯文字 | `.txt` / `.md` 都行 |
